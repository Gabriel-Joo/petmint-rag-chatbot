# 여러 날 입원·여러 번 통원 계산 + 청구 이력 (2026-10-21)

약관의 모든 단위가 하루다(통원·입원 Ⅰ·Ⅱ·Ⅲ 제1조 표 — 자기부담금 "1일당", 한도 "1일당", 수술한 날은 그날만). 총액을 하루치로
계산하던 것을 날마다 계산으로 바꾸고, 연간 총 한도·Ⅲ MRI 회차는 청구 이력(insurance_core.claims)으로 정한다.

## 바뀌기 전 → 후 (고급형Ⅰ, 자기부담금 3만원, 70%, 1일 30만원)

| 사례 | 예전(하루치) | 지금 |
|---|---|---|
| 입원 3일 총 70만원 | 30만원 | 날짜별 칸 → 30만·30만·10만이면 42만 7,000원 / 모르면 30만 ~ 44만 1,000원, 고르게 42만 7,000원 |
| 입원 7일 총 200만원 | 30만원 | 범위 30만 ~ 128만 1,000원, 고르게 125만 3,000원(칸 없이 — 6일 이상) |
| 통원 3번 총 45만원 | 29만 4,000원(많게) | 범위 25만 2,000원 ~ 28만원 |
| 해피(입원 기본형Ⅰ, 올해 474.5만원) 3일 20만원씩 | 11만 9,000원(하루치) | 35만 7,000원 → 남은 연간 한도 25만 5,000원 |
| 뭉치(통원Ⅲ 고급형, 올해 MRI 1번) MRI 120만원 | 81만 9,000원(첫 번째 한도 100만원) | 30만원(두 번째부터 30만원) |

범위는 날짜별로 나뉠 수 있는 모든 경우의 최소·최대(날마다 1만원 이상) — 꺾이는 점 조합을 다 세서 구하고, 1만원 단위 전수 탐색과
같은 값인지 테스트로 확인했다(tests/test_daycalc.py). 고르게 나뉜 추정과 범위 양 끝은 원 미만을 합계에서 한 번 버린다
(날마다 버리면 3일 70만원이 426,999원이 됐다). 날마다 버린 실제 합계는 범위보다 (일수 − 1)원까지 작을 수 있다.

## 청구 이력(가상 — db/fixtures/claims.json, 8건)

| 고객 | 반려동물 | 특약 | 올해 받은 보험금 | 남은 연간 한도 |
|---|---|---|---|---|
| C001 | 초코 | 입원Ⅱ 고급형 | 350만원(2건, 수술 1) | 1,150만원 |
| C001 | 나비 | 통원 기본형Ⅰ | 6만 3,000원 | 493만 7,000원 |
| C006 | 해피 | 입원 기본형Ⅰ | 474만 5,000원(2건, 수술 2) | 25만 5,000원 |
| C006 | 뭉치 | 통원Ⅲ 고급형 | 74만 9,000원(MRI 1번) | 1,425만 1,000원 |
| C009 | 망고 | 통원Ⅲ 기본형(자기부담 5만원) | 9만 1,000원(2건) | 990만 9,000원 |

나머지 7명(C002·C003·C004·C005·C007·C008·C010)은 이력 없음. 지급액은 같은 날짜별 계산으로 냈다.
자기부담금 5만원인 반려동물은 원장에 이미 다섯(보리·레오·까미·모모·망고) 있어 따로 넣지 않았다.

## 검증(로컬 서버, scripts/verify_modes)

- 단위 테스트 전체 102개 통과(새로 daycalc 10 · dayparse 10, amount_answer 8 → 29)
- C010 R1~R15·R18~R26: 통과 140 · 실패 3(R2·R4·R6 — 기존 답 문장, 지난 결과와 같다) · 확인 필요 1(R6)
- C001 R16·R17: 실패 0(초코 — 남은 연간 한도 1,150만원 안내) / C006 R27~R29: 실패 0 / C004 R3: 실패 0
- 첫 실행에서 계산 카드의 year_start(date)가 턴 로그 JSON에 안 들어가 턴이 저장되지 않았다(복원 실패 9건) →
  `model_dump(mode="json")`으로 고치고 테스트를 더했다(TurnLogPayout)
- R26·R29(단독 질문)의 답 문장은 모델이 거절했다 — 카드는 맞다(범위 25.2만~28만원 / MRI 두 번째 30만원). R2 유형, 나중에 본다
- 브라우저(1440·400px): 칸 카드 → [고르게 나눠 넣기] → [계산하기] → 결과 카드 42만 7,000원, 가로 넘침 없음

## 의료비 카드가 뜨는 모든 턴을 코드가 답한다 (2026-10-21, 같은 날 이어서)

되묻기 직후만이던 코드 답(H)을 처음부터 금액을 다 말한 단독 질문까지 넓혔다(`payout.question_turn`) — 카드는 맞는데 모델이
거절했다(R2·R26·R29). 단독 질문도 같은 흐름이라 2~5일 총액이면 날짜별 입력 카드로 묻고(R26 → R30 '잘 모르겠어요' → 범위),
일수를 모르면 하루로 계산했다고 밝히고 다음 턴에 일수를 이어 받는다. 법률비용·한도 카드는 그대로 모델이 답한다.

- 영향 범위: 평가·회귀 질문 129개에는 치료비 금액이 든 질문이 없어 모델 평가는 그대로다. 걸리는 것은 검증 질문 5개뿐
- 검증(로컬): C010 R1~R15·R18~R26·R30 통과 156 · 실패 2(R4·R6 — 기존 답 문장). R2가 이번에 통과(카드·답 30만원).
  C001·C004 실패 0, C006 R27~R29 실패 0(R29 판정 기준에 계산 과정 숫자 81.9만원을 '안 될 값'으로 넣은 내 실수를 고쳐 다시 돌림)
