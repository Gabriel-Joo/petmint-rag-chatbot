# 03 모델

이 서비스의 답은 결국 언어 모델이 쓴다. 다만 모델이 혼자 다 하지는 않는다. 어느 조항을 읽을지는 검색이 정하고(→ 「질문에 맞는 조항 찾기」), 계산처럼 규칙으로 답할 수 있는 것은 코드가 먼저 답한다(→ 「코드가 답하는 질문」). 모델에게 남는 일은 건네받은 약관 발췌를 읽고 상담원 말투로 답을 쓰는 것이다. [docs:02_pipeline/07_finetuning.md:12-16] 이 편은 그 모델을 고르고, 서버에 올리고, 약관에 맞게 가르치고, 재는 과정 전체를 내려다보는 길잡이이고, 자세한 것은 아래 다섯 편에 나눠 두었다.

## 모델 넷이 하는 일

답을 쓰는 모델은 Trillion Labs가 만든 한국어 언어 모델 Tri-7B 하나다. 이 모델 하나가 두 모습으로 돈다. 아무것도 보태지 않은 원본은 일반 모드와 사내규정 모드에서 답하고, 약관으로 따로 가르친 판은 업무특화 모드에서 답한다. [docs:requirements.md:39-43] [docs:02_pipeline/00_model_setup.md:17] 검색 쪽에는 모델이 둘 더 있다. 문장을 뜻이 담긴 숫자 벡터로 바꾸는 임베딩 모델 KURE-v1과, 검색이 가져온 후보를 질문과 하나씩 맞대어 다시 줄 세우는 리랭커 bge-reranker-v2-m3다. [docs:02_pipeline/09_ui_design.md:562-563] 넷째는 서비스에는 나오지 않고 학습 데이터를 만들 때만 일하는 모델이다. Tri-7B가 만든 질문과 답에 틀린 곳이 있는지 판정하는 심판으로 Gemma 4 12B를 쓴다. [docs:02_pipeline/06_quality_check.md:256]

모든 모델은 사내 서버의 그래픽카드 한 장에서 돈다. 바깥의 언어 모델 서비스는 답을 쓸 때도, 학습 데이터를 거를 때도 부르지 않는다. [docs:requirements.md:32] [docs:02_pipeline/06_quality_check.md:233]

## 모델 셋은 바꾸지 않는다

생성 모델(Tri-7B와 그 위에 얹은 학습분), 임베딩 모델 KURE-v1, 리랭커 bge-reranker-v2-m3 셋은 교체하지 않기로 정했다. 재학습이나 검색 개선을 다시 열 때도 이 셋을 고정하고, 나아질 길은 학습 데이터를 짜는 법, 검색 범위와 발췌를 묶는 법, 코드가 먼저 답하는 범위에서 찾는다. [docs:next_rebuild.md:178] 학습 데이터를 다시 만드는 실험에서 다른 모델(Qwen3 14B)에게 답을 쓰게 해 본 적은 있지만, 그것은 한 번의 실험이었고 기본값이 아니다. [docs:next_rebuild.md:178] [docs:02_pipeline/07_finetuning.md:342]

## 약관을 가르치는 길

원본 Tri-7B는 한국어를 잘 쓰지만 펫퍼민트 약관은 모른다. 보험금 지급 기일을 물으면 약관의 기일 대신 흔한 보험 상식으로 답한다. [docs:02_pipeline/00_model_setup.md:112-114] 그래서 약관 원문에서 질문과 답을 만들고, 그 가운데 믿을 만한 것만 남겨, 그것으로 모델을 조금 더 가르친다. 가르치는 것은 약관 내용 자체가 아니라 주어진 발췌를 읽고 답하는 버릇이다. 사실은 매번 검색이 발췌로 건넨다. [docs:02_pipeline/07_finetuning.md:12-16]

질문과 답은 사람이 쓰지 않고 Tri-7B가 약관 원문을 보고 만든다. 만든 것은 13,760건이었고, 코드 검사와 심판과 중복 제거를 거쳐 5,343건(39%)이 남았다(2026-10-14). [docs:02_pipeline/06_quality_check.md:100] [docs:02_pipeline/06_quality_check.md:106] 이렇게 많이 버리는 쪽을 고른 것은, 틀린 학습 예시가 모델에게 자신 있게 틀리는 법을 가르치기 때문이다. [docs:02_pipeline/06_quality_check.md:51]

## 하위 편

모델을 어떤 기준으로 골랐고 서버의 그래픽카드 한 장에 어떻게 나눠 올렸는지, 학습한 모델을 운영에서 어떻게 바꿔 끼우는지는 → 「모델 고르기와 서빙」에 있다.

약관 원문을 얼마만 한 덩어리로 모델에게 건네 질문과 답을 만들게 했는지, 계산과 근거 표기를 왜 모델에게 맡기지 않았는지는 → 「학습 데이터 만들기: FAQ 생성」에 있다. 만든 것을 코드 검사와 심판 모델로 어떻게 걸렀고, 심판을 무엇으로 왜 골랐는지는 → 「학습 데이터 거르기: 검사와 심판」에 있다.

걸러 낸 데이터로 모델을 가르친 방법과, 정답이 발췌에 있는데도 모델이 답을 거절하던 문제와 씨름한 이야기는 → 「파인튜닝과 거절 문제」에 있다. 모델의 답이 얼마나 맞는지 무엇으로 어떻게 재는지는 → 「평가: 재는 법」에 있다.

## 용어 풀이

- 언어 모델: 글을 읽고 이어지는 글을 쓰는 AI. 이 서비스는 Tri-7B를 쓴다
- 임베딩 모델: 문장을 숫자 벡터로 바꿔, 뜻이 비슷한 문장끼리 가깝게 놓이게 하는 모델
- 리랭커: 검색이 가져온 후보 조각을 질문과 한 쌍씩 다시 읽어 순서를 다시 매기는 모델
- 심판 모델: 다른 모델이 만든 질문과 답에 틀린 곳이 있는지 판정하는 모델
- 발췌: 검색이 고른 약관 조각에 그 조각이 부르는 조항을 붙여 모델에게 건네는 글
