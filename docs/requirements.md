## 최종 목표

모델 성능 검증에서 그치지 않고, 실제 서비스로 배포 가능한 수준까지 완성하는 것이다. 사용자가 쓸 수 있는 UI, 여러 사용자가 동시에 접속해도 각 세션의 대화가 서로 섞이지 않도록 격리하는 구조, Kubernetes 기반 배포 인프라까지 전부 프로젝트 범위에 포함했다.

### 비기능 요구사항

- 보안: 모델·데이터 사내 서버 상주, 외부 유출 0건 원칙
- 접근성: 사설망 내부 서버를 외부(모바일)에서도 도메인으로 접속 (Cloudflare Tunnel 이용)
- 운영성: 개발은 로컬에서 uvicorn + vite, 배포는 Kubernetes(Deployment + 롤링 업데이트, replicas 2). ArgoCD가 Git을 기준으로 상태를 유지한다 — 지금은 반영이 수동 Sync이고, 매니페스트가 의도대로 들어가는 것을 확인한 뒤 자동으로 바꾼다 (14번)
- 동시성: 여러 사용자 동시 접속은 FastAPI 비동기 처리 + Ollama 자체 큐로 해결 — 설계이며, 아직 생성을 부르지 않아 검증 전이다. GPU 추론을 몇 개까지 동시에 돌릴지는 `OLLAMA_NUM_PARALLEL`로 정하는데 지금은 설정하지 않아 Ollama 기본값을 따른다. VRAM 예산을 재면서 함께 정한다(09번 7-3절).

## UI 설계 방향: 3탭 구조

- 일반: Tri-7B 원본, 파인튜닝 없음 (R1 — 사내 자체 LLM 구축 충족)
- 업무특화: Tri-7B 파인튜닝 + RAG (R4 — 업무 특화 모델 충족)
- 사내규정: Tri-7B 원본 + RAG (R3 — 사내 전용 정보 응답 충족)

같은 베이스(Tri-7B) 모델 하나로, 탭마다 파인튜닝·RAG 적용 여부를 조합해 서빙한다 — 설계이며 세 탭 모두 아직 더미 답변이다. 반려동물의 종은 검색 단계에서부터 고정한다 — 고객 조회로 반려동물을 고르면 그 개체의 종이 따라온다(여러 마리면 개체 선택). 모델이 종을 스스로 추론할 필요가 없어, 강아지/고양이 약관이 서로 섞여 검색될 위험을 원천 차단한다.

화면 설계는 09번, 상담원의 업무 흐름은 10번, 색·글꼴·캐릭터는 11번 문서다.
