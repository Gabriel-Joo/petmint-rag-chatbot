### 0. 목적

일반·사내규정 두 모드를 실제 검색(search-service)·실제 생성(Ollama)으로 끝까지 돌려, 답변·출처 패널·WS 흐름이 설계대로 나오는지 확인한다. 각 질문은 정답을 미리 적어 두고 눈으로 대조한다.

### 1. 시작 전 준비

- [ ]  rebuild3가 끝났는가(GPU를 쓰는 다른 프로세스 없음 — `nvidia-smi`)

- [ ]  Ollama에 `tri-7b`(일반·사내규정 답변 모델)가 올라와 있는가(`docker exec ollama ollama list`)

### 3. 일반 모드

일반 모드는 검색하지 않는다 — 질문만 베이스 모델(`tri-7b`)로 간다(시스템 프롬프트 없음).

| # | 질문 | 보는 것 |
| --- | --- | --- |
| 1 | 파이썬에서 리스트랑 튜플 차이가 뭐야? | 출처 패널이 비어 있어야 정상 |
| 2 | 반려견 통원 치료비 한도가 얼마야? | 약관인 척 숫자를 지어내는지 관찰(통과/실패 아님) |
| 3 | 쿠버네티스가 뭔지 자세히 설명해줘 | 스트리밍이 끊기지 않는가 |
| 4 | (1번 뒤, 같은 세션) 그럼 언제 튜플을 써? | 앞 대화를 기억하지 못하는 것이 기대 결과(멀티턴 없음) |

- [ ]  1 — 출처 패널이 비어 있다(`sources` items가 빈 목록)
- [ ]  2 — 관찰 기록: 숫자를 지어냈는가, 지어냈다면 무엇을
- [ ]  3 — 끝까지 끊기지 않고 흐른다(긴 답변, 최대 300토큰에서 멈추는 것은 정상)
- [ ]  4 — 앞 대화를 기억하지 못한다(기억하면 오히려 이상하다 — 멀티턴이 없는데 기억했다면 어디서 이력이 들어갔는지 본다)

> 4번 주의: 지금 코드에는 멀티턴이 없다 — 질문 재작성(`answer.rewrite_question`)이 비어 있고, 일반 모드는 이번 질문 하나만 보낸다(대화 이력을 넣지 않는 설계, 09번 5절).

> 3번 주의: 답변 길이는 `num_predict` 300토큰에서 끊긴다(`answer.LLM_OPTIONS`) — 문장 중간에서 멈추면 그것이 이유인지 먼저 본다.

### 4. 공통

- [ ]  WebSocket 메시지 순서: 일반·사내규정은 sources → token → references → done (개발자 도구 Network → WS). calc는 오지 않는다
- [ ]  모드 전환: 일반 → 사내규정 → 일반 — 모드마다 세션이 따로이고, 돌아왔을 때 앞 대화가 남아 있다
- [ ]  새로고침 후 이전 턴 표시 — 질문·답변·출처 패널이 그대로(`GET /api/sessions/{id}`의 turns)
- [ ]  브라우저 콘솔 에러 없음(React key 경고 포함)

> `calc`(계산 카드)는 업무특화 모드에서 치료비가 든 질문에만 온다(sources → calc → token → references → done). 일반·사내규정에 calc가 오면 이상하다.
>
> 실패하면 `error` 메시지의 code로 원인을 가른다 — `search_unavailable`(search-service·hr_regulation), `llm_unavailable`(Ollama), `internal`(그 밖, 서버 로그).
