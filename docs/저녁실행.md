### 7. 어댑터를 GGUF로 변환 → ollama create

- **무엇**: select가 고른 LoRA 체크포인트를 베이스에 병합 → GGUF f16 → Q4_K_M → Ollama `kabyul-tri-7b-rag1-rebuild3`. 베이스(`tri-7b`)와 같은 Q4_K_M·매개변수로 맞춘다(10번 문서 8절 — 다르면 모드 간 차이가 양자화 차이인지 가를 수 없다). **처음 하는 작업이다**(`models/merged/`가 비어 있다)
- **명령**

```
# 7-1 병합(CPU로 충분, 호스트 램 약 15GB — 8번 VM 증설 전에 한다)
CUDA_VISIBLE_DEVICES="" ~/llm_env/bin/python - <<'EOF'
import json, torch
from pathlib import Path
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer
sel = json.load(open("models/lora_adapter/rag-1_7099건_rebuild3/ckpt_select.json"))
src, out = Path(sel["best_path"]), Path("models/merged/kabyul-tri-7b-rag1-rebuild3")
base = AutoModelForCausalLM.from_pretrained("models/base/Tri-7B", dtype=torch.bfloat16)
PeftModel.from_pretrained(base, str(src)).merge_and_unload().save_pretrained(out, safe_serialization=True)
AutoTokenizer.from_pretrained("models/base/Tri-7B").save_pretrained(out)
print("병합:", src, "→", out)
EOF
# 7-2 GGUF f16 → Q4_K_M
L=~/AI_programming/notebooks/llama.cpp
~/llm_env/bin/python $L/convert_hf_to_gguf.py models/merged/kabyul-tri-7b-rag1-rebuild3 --outtype f16 \
  --outfile models/gguf/kabyul-tri-7b-rag1-rebuild3-f16.gguf
$L/build/bin/llama-quantize models/gguf/kabyul-tri-7b-rag1-rebuild3-f16.gguf models/gguf/kabyul-tri-7b-rag1-rebuild3-Q4_K_M.gguf Q4_K_M
# 7-3 Ollama 등록(베이스와 같은 매개변수 — models/gguf/Modelfile.tri7b)
printf 'FROM /tmp/kabyul-tri-7b-rag1-rebuild3-Q4_K_M.gguf\nPARAMETER num_ctx 8192\nPARAMETER temperature 0.3\n' \
  > models/gguf/Modelfile.kabyul-tri-7b-rag1-rebuild3
docker cp models/gguf/kabyul-tri-7b-rag1-rebuild3-Q4_K_M.gguf ollama:/tmp/kabyul-tri-7b-rag1-rebuild3-Q4_K_M.gguf
docker cp models/gguf/Modelfile.kabyul-tri-7b-rag1-rebuild3 ollama:/tmp/Modelfile.kabyul-tri-7b-rag1-rebuild3
docker exec ollama ollama create kabyul-tri-7b-rag1-rebuild3 -f /tmp/Modelfile.kabyul-tri-7b-rag1-rebuild3
docker exec ollama ollama list | grep -E "tri-7b"
```

- **시간**: 병합 5~10분 · f16 변환 5분 · 양자화 3~5분 · create 1분 — 합 15~20분(추정). 디스크 약 35GB(병합본 15 + f16 15 + Q4 4.6 — 여유 378GB)
- **성공**: `ollama list`에 `kabyul-tri-7b-rag1-rebuild3 … 4.6 GB` 안팎과 `tri-7b:latest`. 짧은 확인 —

```
curl -s http://localhost:11434/api/chat -d '{"model":"kabyul-tri-7b-rag1-rebuild3","stream":false,"messages":[{"role":"user","content":"[약관 발췌]\n[발췌 1] 테스트\n자기부담금은 3만원입니다.\n\n[질문]\n자기부담금이 얼마예요?"}]}' | python3 -c "import json,sys; print(json.load(sys.stdin)['message']['content'])"
```

- **실패하면**: 병합은 `best_path`와 어댑터의 `adapter_config.json`(베이스 경로), 변환은 llama.cpp 출력(아키텍처 미지원·토크나이저), create는 `docker exec ollama cat /tmp/Modelfile.kabyul-tri-7b-rag1-rebuild3`
- **건너뛰면**: 12번(로컬)과 10번 뒤 클러스터에서 업무특화가 `llm_unavailable` — 없는 모델 이름을 부른다

### 8. VM 메모리 4096 → 8192 (vagrant reload)

- **무엇**: 노드 네 대의 메모리를 8192로. 한 대씩 비우고(drain) 재시작한다 — 한꺼번에 하면 앱·MySQL·터널이 다 멈춘다. 클러스터 배포(9·10번) 전에 해서, 배포한 뒤 다시 내려가지 않게 한다
- **명령**

