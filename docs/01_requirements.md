# 01. 요구사항

## 프로젝트 한 줄 요약

시나리오: 보험사 상담원이 복잡한 약관 조항을 매번 PDF에서 찾아보는 대신, 사내 RAG 챗봇에 물어보고 근거와 함께 바로 답을 받는다. (구체적으로는 메리츠화재 홈페이지에 공개된 '펫퍼민트' 반려동물 보험 약관을 실제 데이터로 사용했다.)

## 최종 목표

모델 성능 검증에서 그치지 않고, 실제 서비스로 배포 가능한 수준까지 완성하는 것이다. 사용자가 쓸 수 있는 UI, 여러 사용자가 동시에 접속해도 각 세션의 대화가 서로 섞이지 않도록 격리하는 구조, Kubernetes 기반 배포 인프라까지 전부 프로젝트 범위에 포함했다.

## 고객 요구사항

- 작업지시서: 사내LLM_최종프로젝트_지시서.docx 기준

### 기능 요구사항 (R1~R4)

| 번호 | 요구사항 | 비고 |
| --- | --- | --- |
| R1 | ChatGPT와 유사한 LLM 서비스를 사내에 자체 구축 | 외부 클라우드 LLM 사용 시 데이터 유출 우려 |
| R2 | 모바일과 사내 PC 모두에서 채팅 서비스 접속 | 외부 네트워크에서도 접근 가능하게 구성 |
| R3 | 사내 규정 등 자사 한정 정보에도 답변 | 범용 모델로는 불가, RAG 필요 |
| R4 | 자사 업무에 특화된 LLM 모델 제공 | 범용 모델의 한계, 파인튜닝 필요 |

### 비기능 요구사항

- 보안: 모델·데이터 사내 서버 상주, 외부 유출 0건 원칙
- 접근성: 사설망 내부 서버를 외부(모바일)에서도 도메인으로 접속 (Cloudflare Tunnel 이용)
- 운영성: 채팅 서버 systemd 상시 구동, 장애 시 재기동
- 동시성: 여러 사용자 동시 접속은 FastAPI 비동기 처리 + Ollama 자체 큐로 해결
(GPU 추론 자체는 순차 처리되지만, 요청 수신은 동시에 받아 대기열로 관리)

## UI 설계 방향: 3탭 구조

- 일반: Tri-7B 원본, 파인튜닝 없음 (R1 — 사내 자체 LLM 구축 충족)
- 사내 규정: Tri-7B 원본 + RAG (R3 — 사내 전용 정보 응답 충족)
- 업무 특화: Tri-7B 파인튜닝 + RAG (R4 — 업무 특화 모델 충족)

같은 베이스(Tri-7B) 모델 하나로, 탭마다 파인튜닝·RAG 적용 여부를 조합해 서빙한다. 반려동물의 종을 검색 단계에서부터 고정한다 — 가입 고객은 고객 조회로 종이 자동 확정되고, 가입 상담에서만 직접 선택한다(09번 참고). 모델이 종을 스스로 추론할 필요가 없어, 강아지/고양이 약관이 서로 섞여 검색될 위험을 원천 차단한다.
