# docs/

이 폴더에는 성격이 다른 두 종류의 문서가 있다. 섞지 않는다.

폴더 구조는 노션과 같다(2026-11-09). 노션 「02. 파이프라인 설계」 아래 단계 문서는 `02_pipeline/`에, 상위 문서 둘은 이 폴더 바로 아래에 둔다. 운영 기록·체크리스트는 `ops/`에 둔다. 그림은 `img/`.

## 파일 이름 규칙

- **숫자가 있으면 파이프라인 단계 문서**다(`07_finetuning.md`, `09_*.md` ~ `16_*.md`). 번호는 노션의 단계 번호를 따른다(예: 15 = 모니터링). 이 폴더에서 번호를 새로 매기지 않는다.
- **숫자가 없으면 상위 문서이거나 작업 문서**다.
  - 상위 문서: `requirements.md`(노션 01 — 요구사항), `pipeline.md`(노션 02 — 파이프라인·아키텍처).
    노션에서 02는 단계 문서들을 품는 상위 페이지라, 단계 문서와 같은 줄에 번호를 붙이면 헷갈린다. 그래서 상위 문서는 번호를 떼고 이름만 쓴다.
  - 작업 문서: 아래 2절의 표에 있는 것.

상위 문서 둘도 설계 문서다(1절) — 어느 쪽인지는 아래 1·2절의 목록으로 가린다.

## 1. 설계 문서 — 저장소가 원천, 노션은 사본

| 파일 | 노션 |
|---|---|
| `requirements.md` | 01 — 요구사항 |
| `pipeline.md` | 02 — 파이프라인·아키텍처(상위 페이지) |
| `02_pipeline/00_*.md` ~ `02_pipeline/16_*.md` | 각 단계 문서(02의 하위 페이지) |

**원천은 이 폴더다(2026-10-18부터).** 노션은 이 파일들을 옮겨 둔 사본이다.

- 설계가 바뀌면 이 파일들을 저장소에서 직접 고친다.
- 고친 뒤에는 **무엇을 고쳤는지(파일·절·바뀐 내용) 알린다.**
- 노션에서 다시 내보내 이 파일들을 덮어쓰지 않는다. 노션에서만 고친 것은 이 폴더로 옮긴다.

**노션 반영은 자동이다(FOREMAN, 2026-11-09부터).** push 30분 뒤 바뀐 블록만 노션 사본에 옮긴다. 페이지를 새로 만들거나 제목을 바꾸지 않고, 바뀐 페이지에 회색 "마지막 갱신 —" 줄만 붙인다.

- **대상**: 위 표의 20개 — `requirements.md`, `pipeline.md`, `02_pipeline/*.md` 18개. `ops/`, `next_rebuild.md`, 이 `README.md`는 대상이 아니다.
- **노션 모양을 그대로 두는 예외**: 제목 단계, 인라인 코드와 업로드 이미지, 글자는 같고 모양만 다른 블록. 이것들은 git과 달라도 덮어쓰지 않는다.
- **짝은 경로로 맺는다.** 파일을 옮기거나 이름을 바꾸면 노션 페이지와 짝이 끊긴다 — `git mv`·이름 변경은 FOREMAN과 먼저 맞춘다.
- **노션을 직접 고칠 때는 글자가 git과 같아야 한다.** 다르면 FOREMAN이 사람이 고친 페이지로 보고 그 페이지 반영을 멈춘다. 멈춘 페이지는 덮어쓰지 않고 사람에게 알린다.

## 2. 작업 문서 — 저장소에만 있다

노션에 옮기지 않고 이 폴더에만 있는 문서다.

- 번호를 붙이지 않는다(단계 문서 번호 체계 밖).
- 측정·작업 계획·지시서처럼 진행 중인 작업을 위한 문서다.

| 파일 | 내용 |
|---|---|
| `next_rebuild.md` | 다음 FAQ·파인튜닝 재구축 지시서 |
| `TODO.md` | 나중에 할 일 — 정해 두고 미룬 것(무엇·언제·조건·근거) |
| `ops/저녁실행.md` | rebuild3 뒤 실행 순서서(명령·시간·성공·실패·건너뛰면) |
| `ops/배포기록.md` | 배포·알림 시험처럼 코드 변경 없이 배포를 일으킨 커밋의 기록 |
| `ops/모드검증.md` | 일반·사내규정·업무특화 모드 검증 체크리스트(질문·정답 — `scripts/verify_modes.py`·`scripts/verify_cases.py`와 같다) |

측정 기록과 검수 결과는 `docs/`가 아니라 `data/review/`에 둔다.
