# 원고 쓰는 법

> 상태: 2026-11-19 새로 씀. 노션 기술문서 원고(`notion/`) 차례를 정했고 00편부터 쓰는 중이다(문서 정리 D단계).

펫퍼민트 문서는 두 벌이다. `notion/`은 비개발자도 읽는 노션 기술문서 원고이고, `docs/`는 이 저장소에서 일하는 사람과 세션이 보는 개발자 문서다. docs는 git에만 둔다. 런슈즈 `docs/style_guide.md`를 본으로 삼았다. 두 벌은 읽는 사람이 달라 편 나눔이 다르다. 원고는 서비스를 소개하는 차례로 짜고, docs는 만든 단계별로 둔다(2026-11-19 사용자). [c:f7bd15c]

모든 저장소에 같은 원고 기준은 FOREMAN `docs/manuscript_rules.md` 한 곳에 있고, 이 파일에는 이 저장소만 다른 것만 둔다. 아래에서 「기준 문서」는 그 파일이다.

#### 1. 원고 차례 (고정)

원고의 첫 `# ` 줄은 「번호 제목」이다(예: `# 00 전체 그림`, `# 01-01 약관 PDF를 조각내기`). 하위 편은 큰 편 이름의 폴더에 둔다(`notion/01_data/01_chunking.md`가 01-01). 「바탕 docs」 칸은 그 편이 주로 기대는 docs 편이다. 「사진」 칸이 「넣음」인 편은 운영 화면 사진을 넣는다. 사진은 문서 정리 E단계에서 포트폴리오 사진과 한 번에 찍고, 그 전에는 원고에 `<!-- 사진 자리: 어떤 화면 -->` 한 줄만 둔다(2026-11-19 사용자).

원고에 넣지 않는 docs: README(폴더 안내), TODO(할 일), 기록 폴더(`docs/archive/`, `docs/ops/`). 할 일은 원고에 적지 않는다(기준 문서 1절). 10편은 맨 뒤에 두고 결정으로 묶으며, 조건 묶음은 그 편 맨 끝이다(기준 문서 2절 「한계 편의 꼴」).

#### 2. 머리 주석

모든 편(원고와 docs 모두)의 맨 첫 줄부터 둔다. 게시기가 노션 판에서 뗀다.

```
<!--
다루는 곳: 그 편이 덮는 저장소 경로(쉼표로)
읽은 커밋: 그 편을 쓰며 실제로 연 커밋
-->
# 00 전체 그림
```

읽은 커밋은 편마다 적는다. 근거의 줄 번호는 읽은 커밋의 파일 기준이다. 그 커밋 뒤에 생긴 파일은 근거로 걸 수 없다.

#### 3. 근거 표시

사실을 말하는 문장 끝에 단다. 숫자나 인용이 있는 문장에는 반드시 단다.

- code 표시: 저장소 맨 위에서 본 파일이나 폴더, 줄 하나나 줄 범위. 예: [code:data/rag_context.py:439]
- docs 표시: `docs/` 아래 경로, 줄을 붙일 수 있다. 예: [docs:02_pipeline/07_finetuning.md]
- c 표시: 이 저장소의 커밋. 예: [c:f7bd15c]

원고는 docs를 근거로 걸어도 된다. docs가 이미 코드와 맞춰 본 글이기 때문이다(2026-11-19 A단계). 다만 docs에 없는 사실을 원고에서 새로 만들지 않는다. `docs/archive/`는 옛 기록이라 까닭(왜 바꿨나)을 가져올 때만 쓴다.

다른 원고 편을 가리킬 때는 화살표 뒤에 그 편 제목을 낫표로 감싸 쓴다. 제목은 위 차례의 제목 그대로이고 번호는 붙이지 않는다. 화살표 뒤에 화면 글이나 사람 말을 옮길 때는 큰따옴표를 쓴다.

#### 4. 원고(notion/) 쓰는 법

독자, 깊이, 말투, 문단과 목록, 어려운 말 풀기, 지금 상태만 쓰기, 왜를 쓰기, 줄표와 가운뎃점은 기준 문서 1, 2, 4절을 따른다. 아래는 이 저장소만 다른 것이다.

- 한 편은 대략 3,000~5,000자, 큰 편 머리(01, 02, 03, 05)는 그보다 짧아도 된다. 길이와 깊이는 런슈즈 `notion/`에 맞춘다
- docs를 그대로 옮기지 않는다. 표와 목록을 그대로 나르지 않고 문장으로 읽히게 새로 쓴다(2026-11-19 사용자)
- 숫자에는 잰 날짜를 붙인다(예: 「강아지 928건(2026-10-12)」)
- 약관은 메리츠화재가 공개한 실제 상품 약관이고, 고객과 직원은 가상 인물이라는 것을 숨기지 않는다. 고객이나 상담 수를 말하는 편은 그 사실을 함께 적는다
- 원고에 넣지 않는 것(점검이 막는다): IP 주소, 도메인, 홈 경로, 토큰 꼴 문자열, 포트 번호. 역할로 쓴다(예: 「호스트에서 도는 검색 서버」)
- 편의 끝은 이 순서로 둔다(없으면 뺀다): 「알려진 한계」(목록), 「용어 풀이」(목록). 여러 편에 걸치는 한계는 10편에 한 번만 적고, 편에는 가리키는 한 줄만 둔다

#### 5. 개발자 문서(docs/) 쓰는 법

공통 뼈대(0 한 줄 요약 ~ 5 검증 항목)는 `docs/pipeline.md` 6절에 있다. 맨 위 머리 주석과 근거 표시는 위 2, 3절과 같다. 남은 한계 절은 「한계」(안 하는 까닭을 붙임)와 「조건: 우리가 고르지 않은 것」으로 나눈다. 아직 할 일은 `TODO.md` 한 곳에 둔다.

```
~/AI_programming/foreman/.venv/bin/python ~/AI_programming/foreman/tools/docs.py --repo . check      # 틀린 것 0이어야 한다

```
